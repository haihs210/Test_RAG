# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A reference implementation of **CF-SCD (Coverage Fingerprint - Spatial
Change Detection)**, an algorithm for turning UE Report data (via a Mentor
coverage database) into automatic radio-coverage anomaly detection,
root-cause analysis, and a Coverage Health Score. See
`docs/algorithm_analysis.md` (Vietnamese) for the algorithm write-up this
code is based on, and `README.md` for the full usage/data-ingestion story.

## Commands

```bash
pip install -r requirements.txt

# Synthetic data end-to-end: generate -> full 7-step pipeline -> alerts.csv + dashboard.html
python scripts/run_demo.py --n-cells 120 --n-days 35 --samples-per-cell-day 1500 --out out/

# Real Mentor export -> Coverage Fingerprint only (steps 1-2; see "Two data modes" below)
python scripts/run_real_data_demo.py path/to/raw_mentor.txt \
    --cell-config path/to/cell_config.xlsx --out out_real/

# Tests
python -m pytest tests/ -q
python -m pytest tests/test_pipeline.py -q                       # one file
python -m pytest tests/test_pipeline.py::test_alerts_have_actionable_fields -q  # one test
```

There is no lint/typecheck config in this repo. The full test suite takes
~25-40s because `tests/test_pipeline.py` runs the entire pipeline on an
80-cell/35-day synthetic dataset as a module-scoped fixture shared across
several assertions - don't add a similarly heavy fixture per-test.

`out/` and `out_real/` are gitignored, generated by the scripts above -
never hand-edit or commit into them.

## Architecture

### Two data modes, one pipeline

The seven CF-SCD steps (`pipeline.CoverageIntelligencePipeline.run`) only
ever consume a UE Report DataFrame with columns `cell_id, site_id, date,
distance_m, bearing_deg, rsrp_dbm` (plus a `cells` table with
`peer_group`/`azimuth_deg`/etc. and optionally an `alarms` table). Two
independent producers build that shape:

- **Synthetic** (`synthetic.py`): vectorized generator (topology + 5 named
  anomaly scenarios: OUTAGE, SHADOWING, TILT_POWER_DRIFT, AZIMUTH_DRIFT,
  OVERSHOOT) used by `scripts/run_demo.py` and `tests/test_pipeline.py` to
  exercise the full 7-step pipeline, since it can fabricate the 7-30 days
  of history steps 3-6 need.
- **Real** (`loader_mentor.py` + `loader_cell_config.py`): parses actual raw
  network exports. `load_mentor_export` gets serving-cell-only rows with
  measured distance; `load_mentor_power_measurements` +
  `loader_cell_config.attach_geometry` additionally pulls every
  candidate/neighbor cell's `EC_1..EC_11` reading (not just the serving
  cell's `EC_0`) and computes distance/bearing geometrically from real site
  coordinates - this is several times more usable samples per cell than the
  serving-only path. **A single real export is one time snapshot**, so
  `scripts/run_real_data_demo.py` only exercises Coverage Fingerprint
  extraction (steps 1-2), not baseline/detection/RCA/CHS - those need the
  same export repeated daily and concatenated.

### The 7-step pipeline (`pipeline.py` orchestrates all of it)

1-2. `features.compute_fingerprints` bins UE Report rows into a
   `FingerprintTable` (`scalar` + four wide bin tables: `ring`, `direction`,
   `grid`, `ring_direction`). Every bin table carries `{prefix}_{i}_mean`,
   `_density`, `_count`, and `_confidence` (`count / (count +
   confidence_half_count)`) - this reduces raw UE Report volume (millions of
   rows/day) down to one row per `(cell_id, date)`, which is what makes
   steps 3-6 tractable on a laptop. `bearing_deg` may be NaN for some rows
   (real data without a known site position); bin columns use nullable
   `Int64` so those rows still contribute to Signal/Distance/Ring but drop
   out of groupby for Direction/Grid instead of crashing.
3. `baseline.py` builds two parallel baselines per cell: `compute_baseline`
   (own trailing history, median/MAD, outlier/incident-day exclusion) and
   `peer_group_baseline` (cross-sectional, same `peer_group` = band+tech,
   same day) - the latter is the fallback for cells too new to have their
   own history (see the OVERSHOOT scenario). `detection.merge_baselines`
   combines them into one `EffectiveBaseline` with a `source` column
   (`"own"`/`"peer"`/`"none"`) that downstream RCA reads.
4. `detection.py` runs three independent detectors (rule-based, Spatial
   Similarity Index on the `ring_direction` map, EWMA+CUSUM+trend-residual
   time series) and combines them via `ensemble_vote` - an alert requires
   `cfg.ensemble_votes_required` (default 2/3) methods to agree.
5. `rca.py` scores each alert against a small hand-written pattern table
   (`_score_patterns`) using the *sign* of `radius_change_signed` (shrink =
   tilt/power drift, growth = overshoot) and direction-bin
   improve/degrade fractions (some sectors improving = azimuth drift;
   only degrading = shadowing), then boosts matching causes with any
   corroborating Alarm and de-prioritizes per-cell causes when neighbor
   cells show correlated anomalies (`spatial_scope = "wide-area"`).
6. `health_score.py` combines 5 weighted components into `chs` (0-100) and
   an Excellent/Good/Warning/Critical class, aggregatable up
   `cells[level_col]` (e.g. `province`) traffic-weighted.
7. `pipeline.FeedbackStore` is separate from `run()` - it's meant to be
   called after engineers verify alerts, and its
   `confirmed_incident_dates()` output feeds into the *next* `run()` call
   to exclude real incidents from future baselines.

### Config is deliberately split by use case

`config.CFSCDConfig.ring_edges_m` default is coarse (6 rings), tuned for
the sample density a production baseline/detection run has and validated
against `tests/test_pipeline.py`'s scenario-detection assertions - **do not
sharpen this default** without re-checking those tests; a past attempt to
default to ~50m rings pushed the synthetic false-positive-rate test from
~0% to ~12% because SSI noise scales with bin count vs. sample density.
`scripts/run_real_data_demo.py` instead builds its own finer
`CFSCDConfig(ring_edges_m=...)` locally, justified by the real script's much
higher per-cell sample density (candidate-cell readings + geometric
distance from real site coords).

### Real-data visualization (`real_data_viz.py`)

`fig_cell_coverage_report` builds a 3-panel per-cell figure sharing one
`coloraxis` across mixed subplot types (`xy` heatmap, `polar` Barpolar,
`xy` scatter) - the polar panel ("coverage rose") draws each ring as a
separate `go.Barpolar` trace with `base`/`r` giving it a radial offset,
`theta`/`width` giving each direction sector its true angular wedge, and
`marker.opacity` (array, per-bar) driven by confidence so sparsely-sampled
wedges visibly fade rather than looking as certain as well-sampled ones.
`build_fingerprint_report` renders all five feature groups (Signal,
Distance, Ring, Direction, Grid) as text - useful when a change should
touch every group consistently (e.g. adding a new confidence formula).
